Depth estimation from video

Listen to this page

Single image depth versus video depth

A navigation aid sees a continuous video, not one photo. Running a single image model on each frame works, but each frame is solved independently. Small changes in lighting or position can shift the predicted scale, so the distance to the same wall jumps up and down from frame to frame. This is called flicker, and it is a lack of temporal consistency.

Using information from consecutive frames

Video offers something a single image cannot: the camera moves, so the same surface is seen from slightly different positions, which gives true geometric depth cues. Monodepth2 [18] uses this during training, learning depth without any labels by predicting how one frame should warp into the next. Luo and colleagues [19] use it at test time, fine tuning a network on a specific video so that all frames agree geometrically. Their results are very stable, but the process runs offline and takes far too long for live guidance.

A practical streaming approach

For a live phone app, a light filter over the per frame distance is a good first step. An exponential moving average (EMA) blends each new reading with the running estimate. A plain EMA has one dangerous property for our use: it reacts slowly to a real obstacle that suddenly appears. The version below trusts any reading that is much closer than expected immediately and only smooths readings that are farther:

class DistanceSmoother:
    """Exponential moving average that still reacts fast to real hazards."""
    def __init__(self, alpha=0.3, jump=0.35):
        self.alpha, self.jump, self.value = alpha, jump, None

    def update(self, d):
        if self.value is None:
            self.value = d
        elif d < self.value * (1 - self.jump):
            self.value = d          # sudden much closer reading: trust it right away
        else:
            self.value = self.alpha * d + (1 - self.alpha) * self.value
        return self.value

This asymmetry is deliberate. A false "closer" reading causes a needless warning. A delayed "closer" reading can cause a collision.

Camera movement and moving objects

A walking user moves forward about one meter every second, so a distance that shrinks steadily is expected and is not noise. Smoothing should therefore follow the trend, not freeze the value. Moving people break a different assumption: geometric methods assume the world is still, so a person walking toward the user can confuse them. Here the single image model is actually helpful, because it estimates each frame on its own.

Why stable estimates matter for a walking user

If spoken distances jump between 1 meter and 3 meters, the user cannot build a mental picture and will soon stop trusting the device. Stability is also a signal: if the depth of one region keeps changing while the camera is still, that region is probably glass, a mirror or a moving object, and its uncertainty should be raised.
